# 쪽 넘김 리더: 워크북 입력은 시트에서 (C안)

2026-10-22 결정, 같은 날 구현. 스크롤 리더는 남기지 않고 교체했다. 운영 규칙은 AGENTS.md "쪽 넘김 리더".

## 결정

리더를 s-growthlab처럼 쪽 넘김(e-book 뷰어)으로 바꾼다면, **쪽 안에는 입력을 두지 않는다.**
워크북 블록은 쪽 안에서 높이가 변하지 않는 카드(질문 · 내 답 두 줄 · [작성하기])로 그리고,
쓰기는 카드를 눌러 여는 시트(모바일은 아래에서, 데스크톱은 가운데)에서 한다.
시트 안에는 지금의 리더 템플릿을 그대로 그리므로 저장 경로(`WorkbookResponsesProvider`)와
AGENTS.md의 응답 규칙은 바뀌지 않는다.

## 왜

비교한 안은 넷이었다.

| 안 | 내용 | 결론 |
|---|---|---|
| A | s-growthlab처럼 입력을 장 사이 모달로 뺌 | 저자가 원고 속 원하는 자리에 블록을 넣는 것과 맞지 않음 |
| B | 쪽 안에서 바로 입력 | 프로토타입까지 만들었으나 iPhone Safari에서 길게 쓰면 블록이 깨짐 |
| **C** | 쪽 안은 카드, 쓰기는 시트 | **채택** |
| D | 스크롤/쪽 넘김을 독자가 고름 | 화면 두 벌 검증. MVP에 무거움 |

B안에서 확인한 것(헤드리스 Chrome + 실기기 Safari):

- 글이 늘면 블록 높이가 바뀌어 쪽을 다시 나눈다. 25줄 입력에 85회(키보드 상황 129회).
- 블록이 쪽 경계에서 잘리지 않게(`break-inside: avoid`) 하면, 쓰는 중에 블록 전체가 다음 쪽으로 넘어간다.
- 키보드가 올라오면 같은 장이 7쪽 → 16쪽이 된다.
- iOS Safari는 키보드가 올라와도 `dvh`를 줄이지 않고 페이지를 세로로 밀어 올린다. 고정 높이 + `overflow: hidden` 구조와 부딪혀 블록이 깨져 보였다(실기기에서 확인, 헤드리스로는 재현 안 됨).

C안은 카드 높이가 답에 따라 변하지 않아 입력 중 다시 나눔이 0회였고, 시트를 닫아도 쪽 위치가 그대로였다.

## s-growthlab에서 가져올 것과 고칠 것

`Yngie-C/s-growthlab`의 `src/components/reader/useVirtualPaginator.ts`(CSS multi-column + `translateX`)가 바탕이다.
그 저장소는 본문이 읽기 전용(Sanity Portable Text)이라 아래 문제를 겪지 않았다.

- `SwipeHandler`가 `window`에서 ←/→를 받아 `preventDefault`한다 → 입력 중·한글 조합 중에는 무시해야 한다.
- 좌우 20% 탭 영역이 입력 요소를 제외하지 않는다 → 워크북 블록·버튼·링크 위는 제외.
- ResizeObserver가 고정 높이 컨테이너만 본다 → 이미지가 늦게 뜨면 쪽 수가 틀린다. 블록 크기와 이미지 `load`도 봐야 한다.
- 보던 위치를 쪽 번호로 지킨다 → 화면 폭·키보드로 쪽 수가 바뀌면 의미가 없다. 요소 기준으로 지킨다.

M0에서 지운 옛 Inspic 페이지네이터(`git show 0157345^:src/hooks/useVirtualPaginator.ts`)는 화면 크기가 바뀌면 1쪽으로 돌아가고,
`MutationObserver(attributes)`가 자동 높이 조절의 style 변경까지 잡아 키 입력마다 다시 나눴다. 가져오지 않는다.

## 구현 (2026-10-22)

`src/components/reader/paged/`

- `usePagedColumns.ts` — 엔진. 프로토타입에서 B안 전용(입력 따라가기, 다시 나눔 횟수)을 뺐다. 쪽 넘김은 움직임 없이 바로 바뀐다(DESIGN.md Motion).
- `turn-input.ts` — 화살표 키·탭·스와이프를 받을지 판정(순수 함수, 테스트 있음).
- `card-summary.ts` · `BlockCard.tsx` — 카드. 상태 문구는 `block-status.ts`.
- `BlockSheet.tsx` — 시트. 포커스 가두기, Esc, 닫을 때 카드 버튼으로 포커스 복귀, 배경 스크롤 잠금, `visualViewport`로 키보드 위에 붙이기.
- `ReaderView.tsx` — 데스크톱은 목차 열 + 한 쪽, 모바일은 한 열. 저장 불가 안내(`UnsavedNotice`)는 장 머리 위, 미리보기 끝(`PreviewEnd`)은 마지막 쪽에 흐름으로 들어간다. 아래 바는 이전/다음 쪽과 "n장 · p / t쪽".

검증 페이지는 `/dev/reader`(`?mode=local|error|preview`)이고, 장이 여러 쪽에 걸치도록 `app/dev/reader/paged-mock.ts`가 본문을 늘린다.
폰으로 볼 때는 `DEV_ORIGINS=<맥 IP> npm run dev` (`next.config.ts`의 `allowedDevOrigins`).

구현하며 고친 함정:

- 모바일 그리드 열이 `auto`면 다단 본문의 폭이 열을 밀어 쪽이 화면보다 넓어진다 → `grid-cols-[minmax(0,1fr)]`.
- 요소의 쪽 번호를 `floor((left + 1) / step)`으로 세면 소수점 픽셀이 쌓여 뒤쪽 쪽의 맨 위 요소를 한 쪽 앞으로 센다. 반올림하면 단 오른편의 버튼을 다음 쪽으로 세어, 버튼에 포커스가 가는 순간 쪽이 넘어가 클릭이 빗나간다 → 단 사이 간격의 절반을 더해 내림.
- 장을 바꾼 뒤 재기 전 한 프레임 안에 또 넘기면 앞 장의 쪽 번호로 새 장을 넘긴다 → `startAt`에서 쪽 상태를 바로 초기화.

## 남은 것

범위는 2026-10-22 합의했다: 스크롤 리더는 교체, 데스크톱은 한 쪽 + 목차, 빈 공간은 카드 높이 고정으로 다룬다.
진행률 저장·글자 크기 설정은 여전히 범위 밖이다(AGENTS.md "MVP 범위에서 제외됨").

- **iOS Safari의 시트.** `visualViewport`로 시트를 키보드 위에 붙였다. 실기기에서 입력 칸이 가려지지 않는지 아직 확인 전(헤드리스로는 재현 안 됨).
- **쪽 아래 빈 공간.** 카드를 질문 한 줄 · 답 한 줄로 낮췄다. 실제 책(s-growthlab 이전본)으로 보고 더 줄일지 정한다.
- **"읽다가 바로 쓰는" 거리감.** 시트 한 번을 거치는 비용을 카드 문구·미리보기로 얼마나 줄일지는 실사용 뒤 판단.
